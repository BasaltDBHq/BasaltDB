## Crash reports

Owner decision of 18 Nov 2026 (phase 1 of the crash-report work). When basalt panics it saves a scrubbed report on the machine and tells the person how to read it and file it. **Nothing is sent by basalt**: it has no receiver, makes no network request for a crash and never sends one by itself. The person decides whether to file a GitHub issue.

- **When.** A panic in a `basalt` command (any command, including `engine` and `mcp`), and a panic inside an MCP tool call in the engine. The tool call ends with `INTERNAL` ([Error codes](error-codes.md#error-codes)) instead of the process; its `personMessage` names `basalt crash show <id>` and `basalt crash report <id>`, and its next step is `STOP`. The engine keeps serving after such a call, so a tool must not leave state half-updated when it panics. A panic outside both (another goroutine) and a Go runtime fatal error (an out-of-memory kill, a concurrent map write) cannot be recovered and leave no report yet.
- **Where.** `crash/` under the engine's `stateDir` for a tool call's panic, and under the default state directory for a panic in `basalt engine` itself (mode `0755`, files `0644` before the umask, so the person can read what a service running as another OS user saved; `basalt crash list` and `show` read the default state directory and the per-user `state/crash` next to the person's config), and `crash/` in the person's `basalt` config directory (`~/.config/basalt/crash` on Linux, `~/Library/Application Support/basalt/crash` on macOS; mode `0700`, files `0600`) for every other command. One file per report, `<id>.json`, the id a UUIDv7. **Retention:** each directory keeps the newest **20** reports; saving one more deletes the oldest.
- **The CLI line.** After a command panics, `basalt` prints one line on stderr, `basalt: crashed; a report was saved: see what it holds with `basalt crash show <id>`, file it on GitHub with `basalt crash report <id>``, and exits `1`. When no directory is writable the line says the report could not be saved.
- **The report** (camelCase JSON, `basalt crash show` prints exactly this and nothing else): `id`, `time` (RFC 3339 UTC), `version`, `os`, `arch`, `goVersion`, `command` (a `basalt` command name, or the MCP tool name for an engine crash; `unknown` when it has no such shape), `kind` (`PANIC`; `FATAL` is reserved for the runtime fatal errors above), `errorCode` (`INTERNAL`), `message` and `stack`.
- **Built from an allowlist, then scrubbed.** Free text never enters the report:
  - `command` is a name from the command list, or a tool name matching `^[a-z][a-z0-9_.-]{0,39}$`, never an argument; `errorCode` matches `^[A-Z][A-Z0-9_]{0,63}$`.
  - `message`: for a Go runtime error (`runtime.Error`: an index out of range, a nil dereference) the runtime's own message, cut to 200 bytes; for any other panic value only `panic value of type <T>`, never the value's text (it can hold SQL, rows, a connection string). A message that looks like SQL is replaced by `<redacted>`; quoted text becomes `<text>`.
  - `stack`: only lines of the shapes the Go runtime prints. A function keeps its name and loses its argument list; a source position keeps its last three path components (`cmd/basalt/main.go:73`); `panic:` lines and anything else are dropped. Cut to 16 KiB.
  - Then everything is scrubbed: the home directory (and any `/Users/<name>`, `/home/<name>`, `C:\Users\<name>`) becomes `~`; the values of the environment (six characters or more) become `<env>`; the machine's host name and IP addresses (with or without a port) become `<host>`; URLs and connection strings become `<url>`; `password=`, `host=`, `user=`, `dbname=`, `token=` and similar key=value pairs lose their value; e-mail addresses become `<email>`.
  - So a report holds no SQL text, table or column names, row values, connection strings, passwords, this machine's host name, IP addresses, paths under the home directory or environment values. A test feeds known secrets through every route (panic values of several types, the stack's arguments, paths, the environment) and fails if one survives.
- `basalt crash list`: the saved reports of both directories (the engine's when the person can read it), newest first, one per line: `<id>  <time>  <version>  <command>`; `No crash reports are saved.` when there are none. Read-only; an agent may run it.
- `basalt crash show <id>`: prints the report, exactly what `crash report` puts in the issue. The id is the whole id. Read-only; an agent may run it. An unknown id is exit `1`.
- `basalt crash report <id>`: builds a pre-filled GitHub new-issue link on `https://github.com/BasaltDBHq/BasaltDB/issues/new` (`title` and `body`) and **the person submits the issue**. The title is `crash(<command>): panic INTERNAL in <version>`. The body is the report's fields and its stack in a code block. The link is at most **6000** characters: the stack is cut from the bottom (the top frames say where it crashed), with a note in the body and on stderr. At a terminal (stdin is a terminal) it opens the link in the default browser; with no terminal, or when no browser opens, it prints the link on stdout. **Under an agent** (an agent marker is set, [Agents and the admin credential](setup.md#agents-and-the-admin-credential)) it opens nothing and prints no link: it prints that the person should run `basalt crash report <id>` in a terminal of their own. The agent gets the link from the `status` tool instead ([MCP tools](mcp-tools.md#mcp-tools), `status`), which names the newest saved report, its file and the issue link, and the person submits the issue.
- **Not here yet** (a later ticket): automatic sending, a receiver, dedupe and a private triage repository. When automatic sending comes it is opt-in (asked once in the person's terminal, saved in config, never from an agent context) with `BASALT_NO_CRASH_REPORTS=1` and a config key to turn it off. Until then there is no switch, because nothing is sent.
